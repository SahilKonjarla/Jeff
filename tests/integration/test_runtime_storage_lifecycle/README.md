# Storage startup lifecycle

Startup and busy-start fixtures exercise readiness, serialized ownership and failure behavior. Controlled actor/storage setup does not by itself prove installed native startup, physical rollback or every contention schedule.

Keep fixture data private/owned and genuinely outside Git. Unavailable storage must not fabricate application readiness, reset state or create another live reader. See [storage implementation](../../../src/jeff/infrastructure/runtime_storage/README.md), [integration policy](../README.md) and [suite map](../../README.md).
