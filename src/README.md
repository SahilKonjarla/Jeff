**Implemented flow:** the installed `jeff` script or `python -m jeff` calls bootstrap, which injects lazy application client/control factories into the CLI. Help does no project I/O; explicit project commands bind a canonical Git root, initialize or inspect declared configuration, and render public-safe typed identity results. `ask` adds deterministic question routing through a Git-read port, with protected-path filtering, escaped metadata, bounded Git subprocesses, and timestamped results. Only explicit start launches the authenticated daemon; init/config/ask route through it without fallback and status composes read-only local/runtime facts. Project/question commands do not launch providers or arbitrary user commands; internal Git reads use narrow validated argv. The separate fresh `execution` group requires an explicit private backend/profile, reviewed literal inputs and exact approval before its owned Docker job.

**Dependencies/security:** only entry points import bootstrap; inner tiers cannot import outer implementations. Domain remains standard-library-only. The [architecture tests](../tests/architecture/README.md) enforce static import directions, not runtime isolation.
