Start/stop/doctor work outside Git. `doctor [--json]` renders the seven-check bounded application report with exit0 for healthy/stopped/uninitialized,1 for required fault/uncertainty and2 for syntax. Live output labels cached active retention; stopped output labels configured retention inactive. No lifecycle/repair action, raw paths/settings/keys, direct SQL or Git execution is added to presentation. Missing optional diagnostics composition returns explicit unavailable rather than fabricated health. Help, command help and syntax do not invoke factories or select runtime paths. While stopped, init/config/ask fail with `daemon_not_running` without project/ignore/registry writes. Status locally validates registration, then obtains read-only runtime facts; it works stopped and never implicitly indexes/initializes. Invalid/unregistered projects retain their errors before runtime selection.

Init/config/ask keep their existing result bodies. Status adds `data.runtime` to the identity fields. Lifecycle uses its own typed control result; start waits for full authenticated dispatcher/storage readiness, stop confirms actual native exit and released ownership. Acknowledgement/caller cancellation alone is not completion.

Success exits 0; fixed application failures exit 1; syntax/no arguments/unknown commands exit 2. JSON bodies remain on stdout, human errors on stderr. Duplicate/uncertain project outcomes also emit only `Request: <uuid>` on stderr (including JSON mode). `debug last [--request-id UUID]` returns scoped bounded receipt/trace metadata. `history [--limit N] [--cursor TOKEN]` returns acceptance-ordered summaries (50default/100max). Help/invalid UUID/limit stay lazy; reads never displace last, index, write access history or clean up. No-history debug fails explicitly; empty history succeeds. Cursor scope/epoch/generation mismatch requires explicit resync. Missing receipt never proves safe retry. No answer replay.

Questions remain deterministic, model-free and project-scoped; protected/submodule exclusions, reversible metadata escaping, actual Git limits/filter refusal and no raw content/diff rendering are unchanged. Questions persist only minimal allowlisted receipt metadata, not answers or raw input. Config/status do not record access history or perform cleanup.

**Phase2 review contract:** `run --profile NAME [--json] -- EXECUTABLE ARG...` records an exact public proposal under a private daemon profile; it does not run it. `approvals show/approve/deny UUID` uses the approval ID; `jobs show UUID` uses the job ID. List pagination uses `--after`/`--limit` (default16/max32), and all review verbs support `--json`. An approved job is blocked with `execution_available:false` and `launch_authority_issued:false`; Phase3 must require fresh review. Declarations are unverified, default profiles are empty, and argv must never contain secrets. Review factories stay lazy for help/syntax; missing daemon/profile fails without fallback. Unlike M02 history/diagnostics, review inspections can expire/retire ledger detail transactionally.

**Dependencies:** application/domain and client presentation libraries (Typer/Pydantic); no infrastructure/bootstrap/provider imports. Concrete composition belongs to bootstrap. No `.env` loading, providers/audio, concrete executor or launch permission in presentation; fresh execution runs only through the daemon's application ports.

**Fresh interface (opt-in activation):** `execution propose --profile NAME --input FILE [--input FILE...] [--request-id UUID] [--json] -- EXECUTABLE ARG...` prepares a fresh literal-file action without approval/start. `execution approve/deny/start APPROVAL_ID --digest REVIEWED_SHA256 [--request-id UUID] [--json]` requires explicit review binding. `execution show/logs APPROVAL_ID [--json]` inspects durable facts/guarded retained text, not legacy job IDs or live tail. Mutation UUID is printed on stderr before the call, generated only if absent; no retry or autoapproval. Start's success is claim acknowledgement, not completion/guest success. Fresh JSON is its own typed metadata envelope with no private claim/controller identities; show omits text, logs label unavailable/retired/expired payloads. Absent/null backend returns execution_unavailable. Configured private-resource/pin failure returns execution_backend_unavailable; retained generation capacity returns execution_backend_capacity, without capability advertisement or cleanup. Base doctor/status readiness does not prove optional engine/image/isolation availability. The published217-case source baseline includes in-process CLI/authenticated transport and bootstrap with synthetic binaries/subprocess traps. Separately, source, noneditable installed-wheel and human manual public-flow proofs passed. Their exit0 jobs prove guarded output/finished replay/normal stop, not actual cap-reaching truncation, nonzero-exit behavior, timeout/cancel or crash recovery.
